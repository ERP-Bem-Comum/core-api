## Como trabalhar (harness)

- **Use `Read` / `Edit` / `Write` / `Grep` / `Glob`, nunca `cat` / `sed -i` / `> arquivo`.** As
  rules de `.claude/rules/` carregam por `path_glob_match`, e o gatilho é a ferramenta dedicada.
  (`gh pr diff` e `git show` por Bash seguem liberados — não são leitura de arquivo do repositório.)
- **Sessão curta.** A compactação derruba as rules e não as devolve. Se a sessão esticar, entregue
  o que tem e reporte.
- Idioma: **PT-BR com acentuação completa** em laudo, commit, PR e comentário.
- **Commit:** PT-BR com escopo + trailer `Assisted-by: AGENT_NAME:MODEL_VERSION`. **Nunca
  `Signed-off-by`.** `Refs #N` **sem** dois-pontos.
- **Gate antes de empurrar:** `pnpm run typecheck && pnpm run format:check && pnpm run lint`.
  O Prettier formata `.md`, então diff só de Markdown **também** reprova no `format:check`.
  **Vermelho não fecha turno**, mesmo vermelho que você não causou.
- Depois do commit rode `git status` de novo — o hook de Prettier reformata **após** o commit.
- **Nunca `npm`. Sempre `pnpm`.**
- ⚠️ **Não rode `pnpm run test:integration`** — ele sobe MySQL via Docker e **derruba a infra de
  dev** no processo.
